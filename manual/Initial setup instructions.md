# Инструкция по начальной настройке

## 1. Назначение и условия применения

Инструкция предназначена для специалистов заказчика (администратора информационной базы и ответственных сотрудников), которым предстоит настроить и ввести в работу два новых механизма — «Обслуживание клиентов» и «Расчёт управленческой зарплаты».

Предприятие уже ведёт учёт в конфигурации «Управление IT-фирмой». Все действия ниже выполняются **не в отдельной тестовой базе, а непосредственно в той информационной базе, где ведётся реальный учёт** — сразу после того, как в неё загружена обновлённая конфигурация (с новыми документами, справочниками и отчётами) и «Проверка конфигурации» в Конфигураторе прошла без ошибок.

Перед началом работы:
- сделайте резервную копию информационной базы
- выполняйте настройку под пользователем с полными правами (администратором).

Дальше — три группы действий: заполнение констант, назначение ролей пользователям, прочие действия.

## 2. Заполнение констант

Новые константы открываются через универсальный список всех объектов конфигурации:

1. В главном меню программы откройте **Все функции**. Если пункта нет в меню — включите его: **Главное меню → Сервис → Параметры…** → флажок «Отображать команду «Все функции»» → **Записать и закрыть**, после чего повторно открыть главное меню.
2. В дереве слева раскройте узел **Константы**.
3. В списке найдите нужную строку по названию и введите значение прямо в колонке «Значение»:

| Константа | Что указать |
|---|---|
| Токен телеграм-бота | Токен, выданный Telegram при создании бота через @BotFather (бота заказчик создаёт самостоятельно, это не часть данной доработки) |
| Идентификатор группы для оповещения | chat_id группы/канала в Телеграм, куда бот должен присылать уведомления о заявках |
| Номенклатура "Абонентская плата" | Позиция справочника «Номенклатура» для ежемесячной абонентской платы — если её ещё нет, создайте заранее в разделе **Номенклатура** |
| Номенклатура "Работы специалиста" | Позиция справочника «Номенклатура» для работ специалиста сверх абонентской платы — создайте заранее аналогично |

До заполнения токена и идентификатора группы сообщения остаются в очереди без ошибок — остальную настройку можно вести не дожидаясь токена от заказчика.

## 3. Назначение ролей пользователям

Поставляются 4 профиля групп доступа — они регистрируются в справочнике «Профили групп доступа» автоматически, при первом запуске после обновления конфигурации. Создавать их вручную не нужно:

| Профиль | Кому предназначен | Основные права |
|---|---|---|
| Специалист | Специалист, выполняющий заявки клиентов | Документы и справочники «Обслуживание клиентов», отчёт «Выработка специалистов» |
| Менеджер | Менеджер, принимающий и планирующий заявки | То же, что у профиля «Специалист» |
| БухгалтерИТФирмы | Бухгалтер, выставляющий акты по абонентским договорам | Массовое создание актов, документы продажи, отчёт «Анализ выставленных актов» |
| КадровикРасчетчик | Кадровик/расчётчик управленческой зарплаты | Весь блок расчёта зарплаты и оба зарплатных отчёта |

Чтобы дать доступ конкретному сотруднику:

1. Раздел **Администрирование** → **Пользователи** — убедитесь, что у сотрудника есть учётная запись для входа в программу (создайте, если её ещё нет).
2. Раздел **Администрирование** → **Группы доступа** → **Создать**.
3. Укажите **Наименование** группы (например, «Специалисты по обслуживанию»), в поле **Профиль** выберите нужный профиль из таблицы выше.
4. В табличную часть группы добавьте пользователей, которым назначается этот профиль.
5. Повторите для каждого профиля, которым будут пользоваться сотрудники заказчика.

Сами профили можно посмотреть (без необходимости редактировать) в разделе **Администрирование** → **Профили групп доступа**.

## 4. Прочие действия, необходимые для работы механизмов

### 4.1. Нормативно-справочная информация

- **Раздел «Обслуживание клиентов» → «Сотрудники»** — внесите специалистов и административный персонал (справочник «Сотрудники»), обязательно указав поле **Категория** («Специалист» или «Административный персонал») — по этому признаку сотрудник попадает в список выбора специалиста в заявках и в календарь загрузки. Этот справочник не связан с учётными записями пользователей из п. 3 — это два независимых списка, заполняются отдельно.
- **Раздел «Расчёт управленческой зарплаты» → «Условия оплаты сотрудников»** — заполните на текущий месяц для каждого сотрудника, по которому будет считаться зарплата: поля **Оклад** и **Процент от работ**. Без записи на нужный месяц документ «Начисление зарплаты» не сможет рассчитать сотрудника за этот месяц.
- **Договоры на абонентское обслуживание** — у клиентов, которых нужно перевести на абонентское обслуживание, откройте карточку контрагента → список **Договоры** → создайте договор с **Видом договора** = «Абонентское обслуживание» и заполните появившиеся после этого поля: **Дата начала**, **Дата окончания**, **Сумма абонентской платы**, **Ставка часа работы**. Без заполненных дат документ «Обслуживание клиента» по такому договору не проведётся.

### 4.2. Расписание регламентного задания уведомлений

Задание «Отправка уведомлений в Телеграм» включено, но поставляется **без расписания**:

1. Раздел **Администрирование** → **Регламентные и фоновые задания**.
2. Найдите в списке «Отправка уведомлений в Телеграм», откройте и задайте периодичность (например, каждые 1–5 минут), сохраните.
3. Убедитесь, что в свойствах информационной базы регламентные задания не заблокированы (в Конфигураторе: **Администрирование → Параметры информационной базы** → флажок «Блокировка регламентных заданий» должен быть снят).

### 4.3. Начальная страница (по желанию)

Обработка «Календарь специалистов» (раздел «Обслуживание клиентов») не выводится на начальную страницу автоматически. При необходимости пользователь добавляет её сам: откройте обработку один раз обычным образом, затем **Главное меню → Вид → Настройка начальной страницы…** → добавьте форму «Календарь специалистов» в одну из колонок → сохраните. Настройка начальной страницы личная для каждого пользователя.

### 4.4. Техническое примечание

Технический график «Календарь рабочих дней», подключённый к регистру расчёта начислений, заполнять вручную не требуется — на результат расчёта он не влияет.

## 5. Контрольный список перед началом эксплуатации

- [ ] Резервная копия информационной базы сделана перед обновлением конфигурации.
- [ ] Обновлённая конфигурация загружена в рабочую базу, «Проверка конфигурации» пройдена без ошибок.
- [ ] Константы заполнены: обе номенклатурные позиции, токен телеграм-бота и идентификатор группы (после получения токена от заказчика).
- [ ] Пользователям назначены группы доступа с нужными профилями (Специалист/Менеджер/БухгалтерИТФирмы/КадровикРасчетчик).
- [ ] Сотрудники внесены в справочник «Сотрудники» с указанием категории.
- [ ] Условия оплаты (оклад/процент от работ) заполнены на текущий месяц для всех сотрудников, по которым считается зарплата.
- [ ] Хотя бы один договор с видом «Абонентское обслуживание» заполнен (даты, сумма, ставка часа) у клиентов, переводимых на новую схему обслуживания.
- [ ] Расписание регламентного задания «Отправка уведомлений в Телеграм» задано.
- [ ] Проверена отправка тестового уведомления в Телеграм.
