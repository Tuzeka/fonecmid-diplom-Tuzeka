# Инструкция по запуску автотестов

Два `.feature`-файла (Vanessa Automation 1.2.043.42), интерфейс на русском, пользователь с полными правами (Администратор). Контрагенты и сотрудники в тестах названы по-разному («СП» / «ВКМ») — запускать один за другим без очистки базы можно, очистка нужна только при повторном запуске одного и того же файла.

## Тест 1: «Сквозной процесс обслуживания клиента» (`ВКМ_СквознойПроцессОбслуживания.feature`)

Менеджер планирует обслуживания на специалистов → Специалист закрывает обслуживания → Бухгалтер массово формирует акты → отчёт «Анализ выставленных актов» сравнивается с эталоном (12 000 руб. по плану и по факту).

### 1.1. Перед запуском

1. Константы заполнены («Все функции» → «Константы», см. «Инструкция по начальной настройке.md»):
   - Номенклатура "Абонентская плата"
   - Номенклатура "Работы специалиста"
2. У отчёта «Анализ выставленных актов» параметр «Период» выведен в быстрый доступ: Конфигуратор → отчёт «ВКМ_АнализВыставленныхАктов» → макет «ОсновнаяСхемаКомпоновкиДанных» → «Настройки» → «Параметры» → правой кнопкой на «Период» → режим отображения «Быстрый доступ» → сохранить макет → обновить конфигурацию базы данных.

Регламентные задания включать не нужно.

Проверка прав доступа по ролям в тест не входит — проверяется вручную (пользователи по «Инструкция по начальной настройке.md», раздел 3).

### 1.2. Окружение Vanessa Automation

1. Подключение к базе из п. 1.1, язык интерфейса русский, пользователь с полными правами.
2. Ожидание фонового задания «Массовое создание актов» — фиксированная пауза `Пауза 30`. Увеличьте при необходимости.

### 1.3. Привязка к текущему месяцу

Отчёт «Анализ выставленных актов» считает фактические суммы за текущий календарный месяц. Даты в сценарии:
- документы «Обслуживание клиента»: `05.09.2026`, `06.09.2026`, `07.09.2026`
- период «Массовое создание актов»: `05.09.2026`
- период отчёта: `01.09.2026` – `30.09.2026`

должны указывать на месяц фактического запуска. Замените подстроку `09.2026` во всём файле на нужный месяц/год.

### 1.4. Повторные запуски

Перед повторным запуском в том же месяце удалите:
- 3 документа «Обслуживание клиента» с описанием проблемы «СКВОЗНОЙ-ТЕСТ-1/2/3»
- документ «Реализация товаров и услуг» по договору «Тестовый абонентский СП» за этот месяц
- при необходимости — контрагента «Тестовый клиент СП», договор «Тестовый абонентский СП», сотрудников «Тестовый специалист СП 1/2»

### 1.5. Результат

Эталон — 12 000 руб. одновременно по плану («ВКМ сумма к выставлению») и по факту («ВКМ сумма фактически выставлено»). Если факт равен нулю при верном плане — проверьте раздел 1.3 (месяц) и константу «Номенклатура "Работы специалиста"» (раздел 1.1).

## Тест 2: «Заявки клиентов» (`ВКМ_ЗаявкиКлиентов.feature`)

Три проверки на документе «Обслуживание клиента»: (а) проведение по действующему договору, (б) отказ проведения вне периода договора, (в) добавление записи в очередь Телеграм-уведомлений при изменении времени/даты/специалиста. Контекст создаёт сотрудника «Тестовый специалист ВКМ», условия его оплаты, контрагента «Тестовый клиент ВКМ» и договор «Тестовый абонентский» (01.01.2026–31.12.2026).

### 2.1. Перед запуском

- язык интерфейса русский, пользователь с полными правами
- константы «Номенклатура "Абонентская плата"/"Работы специалиста"» не нужны
- токен Телеграм-бота заполнять не обязательно

Регламентное задание отправки уведомлений включать не нужно.

### 2.2. Привязка к 2026 году

- период договора «Тестовый абонентский»: `01.01.2026`–`31.12.2026` (Контекст)
- дата документа в проверке отказа: `15.03.2025`

Если запускаете не в 2026 году — сдвиньте обе даты: дата отказа должна быть раньше начала периода договора и раньше сегодняшнего дня, период договора должен покрывать сегодняшний день.

### 2.3. Повторные запуски

Перед повторным запуском удалите:
- сотрудника «Тестовый специалист ВКМ» и его запись в «Условия оплаты сотрудников» (01.01.2026)
- контрагента «Тестовый клиент ВКМ» вместе с договором «Тестовый абонентский»
- 3 документа «Обслуживание клиента», созданных сценарием
- при желании — записи в справочнике «Уведомления Телеграм-боту»

### 2.4. Результат

1. Первый документ (20.03.2026) проводится без предупреждений.
2. Второй документ (15.03.2025) — отказ с текстом «Не удалось провести».
3. Третий документ (изменение времени окончания работ) — очередь «Уведомления Телеграм-боту» непустая в течение 10 секунд.
